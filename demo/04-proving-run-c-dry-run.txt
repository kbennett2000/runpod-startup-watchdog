Cycle 4, live proving run C — --dry-run against a live pod.

The same nginx:alpine pod, still running and still healthy. This run is set up
to fail it on purpose, and to ask for the most destructive action available:

  --success-phrase   a phrase the pod will never print
  --max-minutes 0.5  thirty seconds, so the clock runs out
  --terminate        delete the pod outright, not just stop it
  --dry-run          change nothing

So a real run of this command would have deleted a perfectly healthy pod. The
point is what happens instead. Expected: the timeout verdict, exit code 3 — the
same code the real run would have returned — and the pod untouched.

Worth reading twice: the exit code was 3, the same code a real run would have
returned. A dry run whose exit code did not match the real one would be useless
for testing a script around it. ADR-0004 fixed that rule; this is it working.
